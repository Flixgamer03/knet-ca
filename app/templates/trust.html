Linux-Server in einem Schritt

Lädt das Root-Zertifikat, prüft den Fingerprint, installiert es im System und richtet die certbot-Erneuerung so ein, dass sie der CA vertraut (Debian/Ubuntu, RHEL/CentOS/Fedora/Rocky, Alpine, Arch, Proxmox). Nutzt nur die Ports {{ cfg.public_http_public_port if cfg.public_http_url else cfg.acme_public_port }} und {{ cfg.acme_public_port }} – funktioniert also auch aus einer DMZ, in der die Web-GUI gesperrt ist.

{% set root_src = (cfg.public_http_url ~ "/public/root_ca.crt -o /tmp/ca-root.crt") if cfg.public_http_url else ("-k " ~ cfg.ca_public_url ~ "/public/root_ca.crt -o /tmp/ca-root.crt") %} {{ codebox("oneliner", "curl -fsS " ~ root_src ~ " \\ && openssl x509 -in /tmp/ca-root.crt -noout -fingerprint -sha256 | grep -qi '" ~ (fingerprint|fp) ~ "' \\ && curl -fsS --cacert /tmp/ca-root.crt " ~ cfg.ca_public_url ~ "/public/bootstrap.sh | sudo sh") }}

Bricht der Befehl nach dem zweiten Teil ohne Meldung ab, stimmt der Fingerprint nicht – dann nicht weitermachen.

ACME-Clients

ACME-Directory: {{ acme }}

Voraussetzung: Root-CA ist im System installiert (siehe oben). Die CA prüft per HTTP-01, ob sie den Server unter dem Namen auf Port 80 erreicht.

Standalone (Port 80 frei)

{{ codebox("cb1", "sudo REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt certbot certonly --standalone \\\n --server " ~ acme ~ " \\\n -d myserver." ~ domain ~ " --agree-tos -m admin@" ~ domain ~ " --no-eff-email") }}

nginx / Webroot

{{ codebox("cb2", "sudo REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt certbot --nginx --server " ~ acme ~ " -d myserver." ~ domain ~ "\n# oder\nsudo REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt certbot certonly --webroot -w /var/www/html \\\n --server " ~ acme ~ " -d myserver." ~ domain) }}

Unter RHEL/Fedora lautet der Bundle-Pfad /etc/pki/tls/certs/ca-bundle.crt. Das Bootstrap-Skript setzt die Variable auch für den Erneuerungs-Timer. Erneuerung testen: sudo certbot renew --dry-run --server {{ acme }} – ohne --server prüft certbot beim Probelauf gegen Let's Encrypt Staging und scheitert an internen Namen. Alternativ echte Erneuerung: sudo certbot renew --force-renewal.

{{ codebox("as1", "acme.sh --issue --standalone -d myserver." ~ domain ~ " \\\n --server " ~ acme ~ " \\\n --ca-bundle /path/to/root_ca.crt") }}
{{ codebox("cd1", "{\n acme_ca " ~ acme ~ "\n acme_ca_root /etc/caddy/root_ca.crt\n}\n\nmyserver." ~ domain ~ " {\n reverse_proxy localhost:8080\n}") }}
{{ codebox("tr1", "# traefik.yml\ncertificatesResolvers:\n knetca:\n acme:\n caServer: " ~ acme ~ "\n email: admin@" ~ domain ~ "\n storage: /letsencrypt/acme.json\n httpChallenge:\n entryPoint: web\n\n# Container-Umgebung:\n# LEGO_CA_CERTIFICATES=/certs/root_ca.crt") }}

Root-CA zuerst per Bootstrap-Skript installieren, dann:

{{ codebox("px1", "pvenode acme account register knet-ca admin@" ~ domain ~ " --directory " ~ acme ~ "\npvenode config set --acme account=knet-ca,domains=pve." ~ domain ~ "\npvenode acme cert order") }}

NPM unterstützt keine eigenen ACME-Server. Erzeuge unter Neues Zertifikat ein Zertifikat (z. B. Wildcard *.{{ domain }}) und lade Schlüssel + Fullchain in NPM unter SSL Certificates → Add → Custom hoch.

Root-CA auf Clients installieren

root_ca.cer herunterladen und in einer Administrator-PowerShell:

{{ codebox("w1", "Import-Certificate -FilePath .\\" ~ base ~ "-root.cer -CertStoreLocation Cert:\\LocalMachine\\Root") }}

Alternativ Doppelklick → „Zertifikat installieren“ → „Lokaler Computer“ → Speicher „Vertrauenswürdige Stammzertifizierungsstellen“. Chrome und Edge nutzen den Windows-Speicher.

{{ codebox("m1", "sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/Downloads/*-root.crt") }}

Das Bootstrap-Skript oben funktioniert auch auf Desktops. Manuell (Debian/Ubuntu):

{{ codebox("l1", "sudo cp root_ca.crt /usr/local/share/ca-certificates/knet-ca-root.crt && sudo update-ca-certificates") }}

Chrome/Chromium unter Linux nutzen eine eigene NSS-Datenbank: certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "{{ cfg.ca_name }}" -i root_ca.crt

Firefox nutzt einen eigenen Zertifikatsspeicher. Entweder unter Einstellungen → Datenschutz & Sicherheit → Zertifikate anzeigen → Zertifizierungsstellen → Importieren die Root-CA importieren und „Websites identifizieren“ anhaken, oder unter Windows/macOS in about:config security.enterprise_roots.enabled auf true setzen.

In Safari root_ca.cer öffnen → Einstellungen → Profil geladen → Installieren. Danach unbedingt Einstellungen → Allgemein → Info → Zertifikatsvertrauenseinstellungen öffnen und das volle Vertrauen für die Root-CA aktivieren.

root_ca.crt herunterladen → Einstellungen → Sicherheit → Verschlüsselung & Anmeldedaten → Zertifikat installieren → CA-Zertifikat. Chrome vertraut dann der CA; viele Apps ignorieren vom Nutzer installierte CAs aber absichtlich.

{{ codebox("j1", "keytool -importcert -cacerts -alias knet-ca -file root_ca.crt -storepass changeit -noprompt") }}

In Docker-Images (Debian-basiert):

{{ codebox("j2", "COPY root_ca.crt /usr/local/share/ca-certificates/knet-ca-root.crt\nRUN update-ca-certificates") }}
